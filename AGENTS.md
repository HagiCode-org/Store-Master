# Store Master - Agent Configuration

## Project Overview

Store Master is a cross-platform desktop application for store management, built with Electron, React, and TypeScript.

## Development Commands

### Installation

Requires Node.js 24+ and npm 10+ (`.npmrc` sets `allow-git=all` for Electron tooling git dependencies).

```bash
pnpm install
```

### Development

```bash
# Start development server
pnpm run dev

# Start renderer only
pnpm run dev:renderer

# Start main process watch
pnpm run dev:main
```

### Building

```bash
# Build for production
pnpm run build:prod

# Build for Linux
pnpm run build:linux

# Build for Windows
pnpm run build:win

# Build for macOS
pnpm run build:mac
```

### Type Checking

```bash
pnpm run typecheck:main
pnpm run typecheck:preload
pnpm run typecheck:renderer
```

### Testing and Checks

```bash
# Renderer/main unit tests (Vitest, jsdom)
pnpm run test:renderer

# Typecheck all three targets (regenerates i18n resources first); used by CI
pnpm run build:tsc:check

# Packaging smoke test (also run as part of build:prod)
pnpm run smoke-test
```

`.github/workflows/pr-checks.yml` runs `build:tsc:check`, `build:prod` and `build:linux:dir` on Node 24; `build.yml` builds and releases packages (pushes to `main`, `v*.*.*` tags, manual dispatch with an optional production-signed build). `release-drafter.yml` drafts the next stable release from Conventional Commits via `.github/scripts/release-notes.mjs`; publishing the draft stays manual. Tests live next to sources (`*.test.ts(x)`, e.g. `src/main/storage/__tests__/`).

## Key Files

- `package.json` - Project dependencies and scripts
- `forge.config.js` - Electron Forge configuration
- `tsconfig.json` - TypeScript configuration for main process
- `tsconfig.renderer.json` - TypeScript configuration for renderer
- `tsconfig.preload.json` - TypeScript configuration for preload
- `vite.config.mjs` - Vite configuration for renderer
- `vite.preload.config.ts` - Vite configuration for preload
- `tailwind.config.js` - Tailwind CSS configuration
- `components.json` - shadcn/ui configuration
- `vitest.config.ts` - Vitest configuration (`@` aliases `src/renderer`)
- `hagi18n.yaml` - i18n audit/sync configuration (base locale `en-US`, target `zh-CN`)
- `PRODUCT.md` / `DESIGN.md` - product intent and design system; read before UI changes

## Architecture

- **Main Process** (`src/main/`) - Electron main process code
- **Preload** (`src/preload/`) - Bridge between main and renderer
- **Renderer** (`src/renderer/`) - React application
- **Shared** (`src/shared/`) - Shared types and utilities, including the Microsoft Store listing model (`ms-store-data.ts`, `ms-store-field-registry.ts`), products and GitHub special repos
- **Renderer state** (`src/renderer/store/slices/`) - Redux Toolkit slices (e.g. `msStoreDataSlice.ts`, `productManagementSlice.ts`, GitHub account/repo slices)
- **Storage** (`src/main/storage/`) - JSON file stores under the user data `store/` directory (override with `STORE_MASTER_DATA_DIR`); the repo-level `store/products.json` is checked-in sample data, not the live store

## UI Components

The project uses shadcn/ui components located in `src/renderer/components/ui/`. To add new components:

```bash
cd src/renderer
npx shadcn@latest add [component-name]
```

## Internationalization

The project supports English and Chinese. Translation files are YAML under `src/renderer/locales/<locale>/` (`en-US` is the base, `zh-CN` the target). `src/renderer/locales/generated-locales/` is generated by `pnpm run i18n:generate` (run automatically via `prepare:i18n`) and is gitignored; do not edit it. Use `pnpm run i18n:check` to validate, and `i18n:sync:write` / `i18n:prune:write` to apply `hagi18n` changes.

## Package management

- The repository uses pnpm, pinned in `package.json` `packageManager`. Run `corepack enable` once, then `pnpm install`. `pnpm-lock.yaml` is the only lockfile; do not commit `package-lock.json`.
- Settings live in `pnpm-workspace.yaml`. `allowBuilds` lists the dependencies whose install scripts may run (reviewed individually, `false` means reviewed and denied); review any new dependency that has an install script and add it there.
- A local registry mirror belongs in `~/.npmrc` only. Never commit a `registry=` line or a mirror URL; `pnpm run check:registry` (also run in CI) fails on any non-`registry.npmjs.org` `tarball` in the lockfile and on mirror hosts in tracked files.
- Undeclared imports fail under pnpm's strict layout: declare the package instead of hoisting it.
